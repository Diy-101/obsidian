## Основные абстракции

|АБСТРАКЦИЯ|ПОЧЕМУ ТАК НАЗЫВАЮТ?|КАКУЮ ПРОБЛЕМУ РЕШАЕТ?|ЧТО ДЕЛАЕТ В КЛАСТЕРЕ?|
|---|---|---|---|
|**Namespace**|Из программирования: область видимости, чтобы переменные не пересекались|Один физический сервер → много команд/проектов. Без изоляции все объекты конфликтуют по именам и сетям|Создает **логическую границу** внутри одного кластера. Всё внутри него (поды, сервисы, конфиги) живёт в своём «квартале»|
|**Pod**|«Капсула» (англ. _pod_ = капсула). Плавают «роём» (swarm)|Контейнер = один процесс. Но часто нужен бэкенд + логгер + прокси. Им нужен общий IP, диски, сеть|Минимальная единица запуска. В одном Pod живёт 1+ контейнер, общие сети, общие диски. **Неустойчив** : если упал → K8s просто поднимет новый|
|**Deployment**|«Развёртывание» (англ. _deployment_ = внедрение/распределение)|Ручное управление подами = хаос при падениях, обновлениях, масштабировании|Контроллер, который **следит за желаемым состоянием** . Ты говоришь: «хочу 3 копии», он сам создаст/обновит/откатит поды при необходимости|
|**Service**|В IT «сервис» = доступная услуга/эндпоинт|Поды живут нестабильно (перезапускаются, меняют IP). Как другому приложению достучаться?|Даёт **стабильный DNS-адрес и балансировку** . Связывает поды через `labels`, маршрутизирует трафик, живёт поверх Network Layer|
|**Node**|Узел (англ. _node_ = точка соединения)|Где физически живёт нагрузка?|Компа/виртуалка в кластере. На ней работает `kubelet` → агент, который реально запускает поды по указаниям K8s|

---

```bash
Cluster (Физический/Виртуальный Кластер)
│
├── Namespace (Логическая граница / "Квартал")
│   │
│   ├── Deployment (Контроллер / "Управляющий")
│   │   │
│   │   ├── ReplicaSet (Надзорный / "Счётчик реплик")
│   │   │   │
│   │   │   ├── Pod (1) → Container(s) + Volumes + Network Namespace
│   │   │   ├── Pod (2) → Container(s) + Volumes + Network Namespace
│   │   │   └── Pod (3) → Container(s) + Volumes + Network Namespace
│   │   │       ↑ Если Pod(1) упал → ReplicaSet поднимает новый автоматически
│   │   │
│   │   └── (При обновлении: создаёт новые поды → ждёт готовности → удаляет старые)
│   │
│   ├── Service (Сетевой балансировщик / "Входная дверь")
│   │   ├── Имя: "lotos-utilization"
│   │   ├── DNS: http://lotos-utilization.default.svc.cluster.local
│   │   └── Маршрутизирует трафик к Pod(1/2/3) через метку `app: lotos-utilization`
│   │
│   ├── ConfigMap / Secret (Хранилища конфигов и паролей)
│   │   └── Подвязываются к Deployment → монтируются в Pods как файлы или env
│   │
│   └── NetworkPolicy (Файрвол / "Пропускная система квартала")
│       └── Определяет: кому разрешено ходить к сервисам, кому нельзя
│
└── Node (Физический сервер / "Земля участка")
    ├── kubelet (Агент → запускает поды по заданию K8s)
    ├── kube-proxy (Балансировка сетевых правил)
    └── CNI-плагин (Настройка сетей между подами, например Cilium/Calico)
```

## General commands
- `kubectl get` - list resources
- `kubectl describe` - show detailed information about a resource
- `kubectl logs` - print the logs from a container in a pod
- `kubectl exec` - execute a command on a container in a pod
